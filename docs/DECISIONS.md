# Décisions techniques

Une ligne par décision : date, choix, raison.

- 2026-11-25 : projet calqué sur [Quai](https://github.com/memton80/quai-ssh) et [Quai PDF](https://github.com/memton80/quai-pdf) — même stack (WinUI 3 non packagé, .NET 10, Windows App SDK 2.6.5 avec les mêmes composants neutralisés, CommunityToolkit.Mvvm, Microsoft.Extensions + Serilog, xunit.v3, Inno Setup, CI GitHub Actions avec test de fumée), même découpage Core / App / tests, mêmes règles de version et de release. Le code commun (réglages JSON, mises à jour, localisation `{l:Str}`, thème, dialogues, capture d'écran du test de fumée) est repris de Quai PDF, pas réécrit.
- 2026-11-25 : **les mises à jour sont la priorité n°1** (demande d'Alexandre) : même mécanisme que Quai et Quai PDF (`Updates/`, `UpdateBannerViewModel`, SHA-256 du `digest` GitHub, Inno Setup silencieux avec `/RELAUNCH=1`, `--after-update`, réglage `checkForUpdates`), prouvé par le CI à chaque run, avant toute fonction de mail.
- 2026-11-25 : **WebView2 accepté, verrouillé, uniquement pour afficher le corps des mails** (accord d'Alexandre) — le HTML des mails n'a pas d'équivalent natif dans WinUI 3. Contrepartie de la règle « pas d'application web cachée » de Quai PDF : JavaScript désactivé, HTML nettoyé, politique CSP sans chargement distant, images distantes bloquées par défaut, navigation interdite, liens ouverts dans le navigateur après confirmation, aucun JavaScript livré (contrôlé par le CI).
- 2026-11-25 : CSS jamais dans le HTML (règle d'Alexandre) : gabarit `Assets/Mail/reader.html` sans style, styles dans `Assets/Mail/mail.css` servis par nom d'hôte virtuel ; contrôlé par le CI.
- 2026-11-25 : v1 en IMAP / SMTP avec mot de passe (ou mot de passe d'application) ; OAuth2 Gmail / Outlook en jalon ultérieur — Gmail et Outlook refusent les mots de passe classiques en IMAP, d'où la nécessité de l'OAuth2 pour eux, qui demande d'inscrire l'application chez Google et Microsoft.
- 2026-11-25 : nouvel `AppId` Inno Setup propre à Quai Mail (jamais celui de Quai ou de Quai PDF) : les trois applications s'installent côte à côte.
- 2026-11-25 : réglage `blockRemoteImages` (vrai par défaut) à la place de `showThumbnails` de Quai PDF : confidentialité d'abord (pas de pixel espion).
- 2026-11-25 : partie App portée de Quai PDF (`App` avec `--smoke-test` / `--update-test` / `--after-update`, `MainWindow` et bandeau de mise à jour, `UpdateInstaller`, `DialogService`, `ThemeService`, `ScreenCapture`, `ReswStrings`, `AppServices`, `SmokeUpdate`, `Loc` / `{l:Str}`, `Common.xaml`, réglages, test de fumée), tout ce qui était PDF retiré (rendu, texte, vignettes, document, métadonnées, « Ouvrir avec »).
- 2026-11-25 : WebView2 dans la publication — retirés : `WebView2EnableCsWinRTProjectionExcludeCoreRef` (qui écartait `Microsoft.Web.WebView2.Core.dll`) et la cible qui écartait `WebView2Loader.dll`. **Gardé** : `WebView2EnableCsWinRTProjection=true`, qui active la projection C# de WebView2 (sans lui, WebView2 disparaît) : son choix automatique dépend de `MicrosoftWindowsAppSDKPackageDir`, défini seulement par le paquet `Microsoft.WindowsAppSDK.Runtime`, neutralisé ici (vérifié dans `Microsoft.Web.WebView2` 1.0.3719.77, même constat que Quai).
- 2026-11-25 : « Garder ce brouillon ? » : `DraftChoice` (Garder / Supprimer / Annuler) et `AskKeepDraftAsync` à la place de `SaveChoice` / `AskSaveDraftAsync`, plus parlants pour un brouillon. Garder = enregistré sur cet ordinateur ; si l'enregistrement échoue, la fermeture ou la mise à jour est annulée (jamais de brouillon perdu). Un brouillon vide est retiré sans question.
- 2026-11-25 : brouillons locaux = un fichier JSON par brouillon dans `%LOCALAPPDATA%\QuaiMail\drafts`, écrit d'un bloc (`AtomicFile`), sérialisation générée (`QuaiMailJsonContext`) ; l'identifiant (32 chiffres hexadécimaux) sert de nom de fichier, tout autre identifiant est refusé (pas de chemin fabriqué depuis l'extérieur). Code maison : quelques lignes au-dessus de `System.Text.Json`, aucune bibliothèque n'apporterait plus.
- 2026-11-25 : état de la fenêtre pour la mise à jour = `WindowState` (identifiants du compte, du dossier, du mail ouvert et du brouillon, jamais d'objet, de corps ni d'adresse) en JSON dans `updates/reopen.txt` (`WindowStateStore`) ; écrit par `ShellViewModel.PrepareForUpdateAsync` juste avant l'installateur, lu puis effacé (même illisible) par `RestoreAfterUpdate` dans la version relancée avec `--after-update`. Journal : « Démarrage juste après une mise à jour », « Brouillon rouvert après la mise à jour », « État de la fenêtre restauré après la mise à jour » ; le CI exige les trois.
- 2026-11-25 : le test de fumée répond aux boîtes de dialogue par `DialogService.Choose(résultat)` (le dialogue se ferme avec ce résultat, comme un clic sur le bouton) plutôt que par l'automatisation de l'interface : même chemin de code ensuite, sans dépendre des noms internes du modèle de `ContentDialog`.
- 2026-11-25 : gabarit `Assets/Mail/reader.html` avec une politique CSP stricte (`default-src 'none'`, aucun script, images limitées à `data:` et à l'hôte virtuel) ; l'hôte virtuel de la WebView2 sera `reader.quaimail.example` (`.example` est réservé, il ne peut jamais désigner un vrai serveur).
- 2026-11-25 : icône de Quai Mail = enveloppe blanche sur le fond de la famille Quai (`tools/make_icon.py`, Pillow), même dégradé que Quai et Quai PDF.
- 2026-11-25 : preuve de la chaîne réelle — v0.1.0 puis v0.1.1 publiées par le CI ; chaque fichier de release a son `digest` `sha256:…` (vérifié par `gh api`, et l'installateur x64 téléchargé a bien cette empreinte). La réponse réelle de `releases/latest` (lue sans jeton) est gardée telle quelle dans `tests/…/Updates/Fixtures/releases-latest-v0.1.1.json` : le test vérifie que `UpdateChecker` y voit 0.1.1 plus récente que 0.1.0, avec l'installateur de chaque architecture, sa taille, son empreinte et l'adresse publiée par GitHub. Variante en direct sur l'API (`QUAI_MAIL_LIVE_TESTS=1`), jamais lancée par défaut pour ne pas dépendre du réseau.
- 2026-11-25 : jalon 1 — **MailKit 5.0.0** (MIT, IMAP / SMTP, tire MimeKit) et **Microsoft.Data.Sqlite 11.0.0** (MIT ; cible net10.0 ; SQLite natif par SQLitePCLRaw 3.0.5, Apache-2.0, et le paquet SQLite 3.53.4, domaine public ; win-x64, win-arm64 et linux-x64 pour les tests), versions vérifiées sur nuget.org.
- 2026-11-25 : jamais de connexion en clair : `MailSecurity` n'a que SSL / TLS et STARTTLS (STARTTLS obligatoire, refusé si le serveur ne le propose pas) ; les réglages en clair publiés par un fournisseur sont ignorés. Certificats validés strictement (`SslPolicyErrors.None`, révocation vérifiée) au lieu de la validation par défaut de MailKit, qui tolère certains cas ; aucune exception possible pour l'instant.
- 2026-11-25 : détection des réglages = petite table intégrée des grands fournisseurs (Gmail, Outlook.com, Yahoo, iCloud, AOL, Fastmail, Orange, Free, SFR, La Poste ; valeurs de leur documentation publique, aucune connexion), puis autoconfiguration publiée par le fournisseur lui-même (`autoconfig.<domaine>` et `<domaine>/.well-known/autoconfig`, en HTTPS, sans l'adresse dans l'URL, réponse limitée à 64 Ko, sans DTD), puis supposition `imap.` / `smtp.` à vérifier. **Pas** de base ISPDB de Thunderbird en ligne (un tiers, hors des connexions autorisées), ni de SRV DNS (il faudrait une bibliothèque DNS en plus). Lecteur du format `config-v1.1.xml` écrit ici : aucune bibliothèque NuGet maintenue pour ce format.
- 2026-11-25 : un compte n'est enregistré qu'après une vraie vérification (identification IMAP, puis SMTP sans aucun envoi) ; mot de passe dans le `PasswordVault` (ressource « QuaiMail », identifiant interne du compte, code repris de Quai), jamais dans `accounts.json` ; `--purge-secrets` (repris de Quai) le vide à la désinstallation avec effacement des données, testé par le CI.
- 2026-11-25 : une connexion IMAP gardée ouverte par compte (une opération à la fois), reconnectée à la demande ; dossiers et en-têtes seulement (`ENVELOPE`, `FLAGS`, `UID`, `INTERNALDATE`, `RFC822.SIZE`), par pages de 50 du plus récent au plus ancien (par numéro de séquence), dossiers ouverts en lecture seule (`EXAMINE`). La réception en direct (IDLE) et la reconnexion automatique viennent au jalon 4.
- 2026-11-25 : cache SQLite `cache/mail.db` (dossiers, en-têtes ; schéma versionné par `PRAGMA user_version`, base illisible ou d'une autre version simplement recréée, en-têtes effacés si l'UIDVALIDITY change) ; une erreur de cache n'empêche jamais d'afficher le serveur ; réglage « Vider le cache ».
- 2026-11-25 : tests contre de **faux serveurs IMAP et SMTP écrits ici** (`tests/…/Support`), en TLS et STARTTLS avec un certificat auto-signé créé pendant le test et épinglé : aucune bibliothèque .NET maintenue ne fournit de serveur IMAP de test (GreenMail est en Java). Le faux SMTP refuse et compte tout envoi : les tests prouvent qu'aucun mail n'est envoyé. Le test de fumée utilise un serveur de test en mémoire (`SmokeMailService`), une ressource du coffre à part et aucun réseau.
- 2026-11-25 : jalon 2 — nettoyage du HTML par **HtmlSanitizer 11.0.26** (MIT, avec AngleSharp et AngleSharp.Css, MIT ; version vérifiée sur nuget.org), comme le suggère CLAUDE.md. Réglages en plus de ses valeurs par défaut, trouvés par les tests de mails piégés : éléments de **formulaire retirés** (HtmlSanitizer les garde par défaut), `class` autorisé (sinon les styles du mail sont perdus), `srcset` / `sizes` / `target` / `ping` retirés, `<style>` gardé mais nettoyé (CSS filtré, `@import` distant retiré) ; schémas : liens http / https / mailto, images `cid:` (servies par l'hôte local), `data:image/` (png, jpeg, gif, webp, bmp, pas svg) et http(s) seulement après « Afficher les images ».
- 2026-11-25 : affichage = gabarit `reader.html` + corps nettoyé ; la page et les images jointes sont servies **depuis la mémoire** par `WebResourceRequested` (hôte `message.quaimail.example`), la feuille de style par `SetVirtualHostNameToFolderMapping` (hôte `reader.quaimail.example` → `Assets/Mail`) ; **tout le reste est refusé** par ce même filtre (seconde barrière après la CSP), sauf les images d'un mail pour lequel l'utilisateur les a demandées. Plutôt que `NavigateToString` : pas de limite de 2 Mo, et la page a une vraie origine (CSP, feuille de style). Un en-tête CSP fixe (ni script, ni cadre, ni formulaire) s'ajoute à celle du gabarit ; pour les images distantes, seule la source `img-src` du gabarit est remplacée, par une chaîne exacte vérifiée (gabarit inattendu = rien d'affiché).
- 2026-11-25 : WebView2 verrouillée réglage par réglage (JavaScript, messages web, dialogues, menus, outils de développement, objets hôtes, raccourcis du navigateur, zoom par pincement, balayage, remplissage et mots de passe, barre d'état, page d'erreur, SmartScreen coupés ; prévention du pistage stricte ; pas de compte Windows ni d'extension ; rapports de plantage non envoyés à Microsoft) ; toute navigation, cadre, nouvelle fenêtre ou protocole externe est annulé, un lien cliqué par l'utilisateur passe par une confirmation qui montre **l'adresse réelle et le site** (jamais le texte du lien) avant le navigateur par défaut ; téléchargements et permissions refusés ; données dans `%LOCALAPPDATA%\QuaiMail\webview`, effacées au démarrage et à la fermeture. Runtime absent : message et lien officiel, rien n'est téléchargé.
- 2026-11-25 : un mail est lu sans être marqué lu (`BODY.PEEK[]`), puis marqué lu explicitement à l'ouverture ; lu / non lu et étoile par `UID STORE` dans un dossier ouvert en écriture, refermé sans `EXPUNGE` (rien n'est jamais effacé au passage). Texte brut en repli par le convertisseur `TextToHtml` de MimeKit (liens rendus cliquables), puis nettoyé comme le HTML.
- 2026-11-25 : pièces jointes listées (nom de fichier assaini : sans dossier, caractère interdit ni nom réservé), enregistrées par `AtomicFile.WriteAsync` (fichier temporaire du même dossier puis remplacement : jamais de fichier à moitié écrit), **jamais ouvertes** par Quai Mail ; types exécutables (exe, msi, scripts, raccourcis, macros Office…) signalés par un avertissement dont « Annuler » est le bouton par défaut. Sélecteur `FileSavePicker` du Windows App SDK (repris de Quai PDF).
- 2026-11-25 : jalon 3 — rédaction en **texte brut** (UTF-8) : simple, lisible partout, rien à nettoyer ; citation « Le …, … a écrit : » puis lignes « > » ; un mail reçu seulement en HTML est cité en texte grâce à AngleSharp (déjà présent pour HtmlSanitizer), sans rien exécuter ni charger. Préfixes « Re: » et « TR: » (usage français), sans empilement. Réponse à tous : jamais à sa propre adresse, pas de doublon entre À et Cc. Fil gardé (`In-Reply-To`, `References`).
- 2026-11-25 : **envoi uniquement par le bouton Envoyer**, volontairement sans raccourci clavier (une touche tapée par erreur dans le texte ne doit jamais envoyer). Destinataires vérifiés avant tout (un seul invalide arrête l'envoi), Cci jamais écrits dans le mail (MailKit). Après l'envoi : copie dans Envoyés avec `\Seen`, sauf Gmail et Outlook.com qui la rangent eux-mêmes (pas de doublon) ; si la copie échoue, le mail est quand même parti et l'utilisateur le sait.
- 2026-11-25 : brouillons — enregistrement local toutes les 5 s s'il a changé (minuteur de la fenêtre), copie dans le dossier Brouillons du serveur au plus toutes les 30 s (`APPEND` avec `\Draft`), l'ancienne copie retirée par son UID seul (`\Deleted` puis `UID EXPUNGE` si le serveur a UIDPLUS ; sinon seulement marquée) : **jamais d'EXPUNGE général**. Une copie à la fois : l'envoi et la fermeture attendent celle en cours. Pièces jointes copiées dans `drafts/<id>.files` (le brouillon ne dépend plus du fichier d'origine). « Garder » en quittant : brouillon rouvert au démarrage suivant (comme le promet la question). Dossiers Brouillons / Envoyés trouvés par leur rôle (SPECIAL-USE) puis par les noms courants.
- 2026-11-25 : tests de l'envoi contre le faux SMTP local, qui **reçoit sans rien acheminer** (option `AcceptMail`, désactivée par défaut : sinon il refuse et compte tout envoi) ; faux IMAP avec `APPEND`, UIDPLUS et `UID EXPUNGE`, qui refuse l'`EXPUNGE` général. Le test de fumée envoie au serveur en mémoire du test, jamais sur le réseau.
- 2026-11-25 : jalon 4 — supprimer = **corbeille du serveur d'abord** (dossier reconnu par son rôle SPECIAL-USE, sinon ses noms courants), par `MOVE` (sinon MailKit copie, marque `\Deleted` et n'efface que ce mail avec UIDPLUS) ; sans corbeille, ou depuis la corbeille, suppression définitive **après confirmation** (« Annuler » par défaut), par UID seul ; jamais d'`EXPUNGE` général. Déplacer : menu « Déplacer vers » (dossiers du même compte).
- 2026-11-25 : recherche plein texte **SQLite FTS5** (tokeniseur `unicode61 remove_diacritics 2` : ni accents ni casse), table de contenu externe sur `messages` tenue à jour par des déclencheurs ; index des en-têtes en cache et du texte des mails déjà lus (100 000 caractères au plus) ; chaque mot saisi est mis entre guillemets (préfixe), la syntaxe FTS5 de l'utilisateur n'est jamais interprétée. En complément, « Chercher aussi sur le serveur » (IMAP `SEARCH` objet / expéditeur / texte) dans le dossier de départ. Schéma du cache en version 2 (l'ancien est simplement recréé).
- 2026-11-25 : réception en direct = un « veilleur » par compte (`MailKitMailWatcher`), **connexion IMAP à part** (la principale reste libre), boîte de réception en lecture seule, `IDLE` relancé toutes les 9 minutes (sinon `NOOP` toutes les 2 minutes) ; nouveaux mails = UID supérieur au dernier vu, donc ceux arrivés pendant une coupure sont annoncés à la reconnexion ; reconnexion automatique avec attente croissante (5 s, 15 s, 1 min, 5 min), arrêt si le mot de passe ou le certificat est refusé. Connexion principale : une reconnexion automatique (un essai de plus) quand elle a été coupée entre deux opérations.
- 2026-11-25 : notifications par `AppNotificationManager` du Windows App SDK (application non packagée, inscription au démarrage, retrait à la désinstallation par `--unregister-notifications`) : expéditeur et objet, seulement quand la fenêtre n'est pas au premier plan, réglage pour les couper ; un échec d'inscription laisse simplement l'application sans notifications.
- 2026-11-25 : boîte de réception unifiée (à partir de deux comptes) : les boîtes de réception mêlées par date, par pages, avec une réserve par compte (un compte injoignable n'empêche pas les autres).
- 2026-11-25 : liens `mailto:` (RFC 6068) : `To`, `Cc`, `Bcc`, objet et texte seulement (ni pièce jointe, ni autre en-tête : un lien ne doit rien imposer), brouillon prérempli, jamais envoyé seul. Installateur : ProgID `QuaiMail.mailto` et `RegisteredApplications` (Quai Mail **proposé** dans les applications par défaut ; Windows laisse le choix à l'utilisateur, l'application ne se déclare jamais par défaut elle-même), retirés à la désinstallation ; le CI vérifie les deux. Instance unique par `AppInstance.FindOrRegisterForKey` / `RedirectActivationToAsync` (modèle du Windows App SDK, point d'entrée `Program.cs` à la place de celui généré, `DISABLE_XAML_GENERATED_MAIN`) : un lien cliqué rejoint la fenêtre ouverte ; tests et désinstallation jamais redirigés.
- 2026-11-25 : jalon 5 — connexion OAuth2 **écrite ici** (`Accounts/OAuth`, quelques centaines de lignes testées) plutôt que MSAL.NET (Microsoft seulement) + Google.Apis.Auth (Google seulement, tire le socle Google.Apis) : deux bibliothèques, deux façons d'ouvrir le navigateur et de garder les jetons, pour un même flux standard (RFC 8252 : navigateur système, code d'autorisation, **PKCE S256**, retour sur l'ordinateur même). XOAUTH2 par `SaslMechanismOAuth2` de MailKit (IMAP, SMTP, réception en direct).
- 2026-11-25 : retour local par `HttpListener` sur un port libre : `127.0.0.1` pour Google, `localhost` pour Microsoft (adresse inscrite), repli sur `localhost` si Windows refuse `127.0.0.1` sans droits d'administrateur ; `state` aléatoire vérifié, seules les requêtes portant `code` ou `error` comptent (404 sinon), 5 minutes au plus, dialogue fermé = attente abandonnée. Page de retour en **texte brut** (pas de HTML, donc ni style ni script à servir).
- 2026-11-25 : jeton de renouvellement dans le `PasswordVault` (même entrée que le mot de passe d'un compte classique : retrait du compte et `--purge-secrets` l'effacent sans code en plus), jeton d'accès en mémoire seulement, nouveau jeton de renouvellement enregistré s'il change ; aucun jeton dans `accounts.json` (champ `auth` absent pour un compte à mot de passe : fichiers des versions précédentes inchangés) ni dans les journaux. Autorisation refusée par le serveur ou expirée = erreur `SignInExpired` et **Se reconnecter** (clic droit sur le compte) ; la réception en direct s'arrête puis reprend après la reconnexion.
- 2026-11-25 : identifiants de Quai Mail chez Google et Microsoft **intégrés à la compilation** (`AssemblyMetadata` alimenté par les variables d'environnement `QuaiMailGoogleClientId`, `QuaiMailGoogleClientSecret`, `QuaiMailMicrosoftClientId`, elles-mêmes tirées des secrets du dépôt GitHub), jamais dans le code. Le « secret » d'un client de bureau Google n'en est pas un pour Google (il est dans chaque copie du programme), mais il reste hors du dépôt. Sans eux (dépôt dérivé, compilation locale), les boutons ne s'affichent pas ; le test de fumée vérifie que la compilation les contient exactement quand les secrets existent, et rejoue toute la connexion contre un fournisseur simulé (navigateur qui suit le retour local, jetons en mémoire).
- 2026-11-25 : Gmail demande le champ d'application restreint `https://mail.google.com/` (seul accès IMAP / SMTP proposé par Google) : sans validation par Google (examen et audit de sécurité annuel payant), l'application reste en mode test (100 testeurs inscrits, autorisation redemandée tous les 7 jours). Choix assumé pour la 0.6 ; le mot de passe d'application reste proposé aux autres utilisateurs de Gmail.
